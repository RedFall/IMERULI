# ROLE

Ты выступаешь как **Senior Art Director + Product Design Reviewer + Final Visual QA**.

Перед тобой уже работающий продукт.

Функциональность сейчас не является основной задачей.

Твоя задача — провести **визуальную доработку существующего сайта** и поднять его воспринимаемое качество до уровня production-grade premium experience.

Целевая оценка:

**Visual Quality: 9–10/10**

Не пытайся добиться этого количеством эффектов.

Высокая оценка означает:

- единый арт-дирекшен;
- сильную композицию;
- стабильную визуальную иерархию;
- согласованное масштабирование между viewport;
- намеренное responsive-поведение;
- качественную работу с глубиной;
- понятное визуальное повествование;
- хорошую читаемость;
- отсутствие ощущений prototype / breakpoint compromise;
- отсутствие визуально случайных решений.

# CURRENT VISUAL PROBLEMS

Считай следующие проблемы подтверждёнными и требующими исправления:

1. Desktop, Tablet и Mobile воспринимаются как три разных арт-дирекшена.

2. Главный заголовок меняет не только размер, но и композиционную роль:
   - Desktop — огромный центральный элемент;
   - Tablet — уменьшенный и смещённый;
   - Mobile — снова крупный доминирующий элемент.

3. Масштаб ключевых сцен и объектов непоследователен между viewport.

4. Стол, печь, квеври и другие композиционные объекты не сохраняют понятную относительную визуальную иерархию.

5. Горная панорама занимает существенно разную композиционную роль:
   - Desktop — нижний план;
   - Portrait — значительная часть viewport.

6. Из-за responsive-перестройки меняется ощущение глубины пространства и направление визуального движения.

7. Подписи сцен не имеют стабильной системы:
   - меняется размер;
   - меняется положение;
   - меняется расстояние до объекта;
   - иногда подпись воспринимается как случайно прикреплённая.

8. Последовательность сцен воспринимается скорее как появление отдельных коллажей над общей декорацией, чем как путешествие через единое пространство.

9. Финальная интерьерная сцена слишком тёмная.

10. Финальный заголовок и CTA недостаточно отделены от фона и теряют визуальный приоритет.

11. Tablet выглядит как техническая интерполяция между Desktop и Mobile, а не как самостоятельно спроектированная композиция.

# PRIMARY OBJECTIVE

Не исправляй эти проблемы локально по одной.

Сначала сформулируй **единый визуальный закон**, которому должны подчиняться все viewport.

Ответь до начала исправлений:

## Visual Intent

Что пользователь должен чувствовать при прохождении страницы?

## Spatial Model

Как устроено виртуальное пространство?

Что находится:

- foreground;
- middle ground;
- background.

## Camera Model

Как ведёт себя условная камера:

- движется вперёд;
- приближается;
- проходит мимо объектов;
- изменяет глубину;
- перемещается по временной последовательности.

## Scale Model

Какие объекты являются:

- доминирующими;
- вторичными;
- фоновыми.

И какие относительные масштабы необходимо сохранять между viewport.

## Typography Model

Какую композиционную роль имеют:

- hero title;
- scene labels;
- supporting text;
- CTA.

## Responsive Philosophy

Какие свойства должны сохраняться между Desktop / Tablet / Mobile, а какие разрешено адаптировать.

Только после определения этой системы переходи к визуальной коррекции.

---

# PRINCIPLE 1 — ONE ART DIRECTION

Desktop, Tablet и Mobile не должны выглядеть как три независимых дизайна.

Они должны восприниматься как:

> одна и та же сцена, снятая разными камерами / объективами.

Разрешается изменять:

- crop;
- framing;
- spacing;
- положение объектов;
- размер текста;
- количество свободного пространства.

Нельзя без сильной причины изменять:

- смысл композиции;
- визуальную иерархию;
- роль объекта;
- направление движения;
- относительную значимость сцены.

---

# PRINCIPLE 2 — RESPONSIVE IS NOT SCALING

Не пытайся просто уменьшать Desktop.

Каждый major viewport должен иметь намеренно спроектированную композицию.

Создай минимум три композиционных режима:

## Desktop

Широкая кинематографичная композиция.

Используй горизонтальное пространство для:

- глубины;
- окружения;
- крупных сцен;
- controlled negative space.

## Tablet

Не считай Tablet уменьшенным Desktop.

Не считай Tablet увеличенным Mobile.

Спроектируй отдельную композиционную систему.

Особенно проверь:

- 768–1024 px;
- portrait tablet;
- landscape tablet;
- промежуточные размеры.

Tablet должен выглядеть намеренно спроектированным.

## Mobile

Используй вертикальное пространство как самостоятельное преимущество.

Не пытайся воспроизвести desktop-композицию целиком.

Сохрани:

- иерархию;
- ощущение путешествия;
- ключевые объекты;
- глубину;

но адаптируй framing под portrait.

---

# PRINCIPLE 3 — SCALE CONSISTENCY

Создай визуальную шкалу основных объектов.

Для каждого ключевого объекта зафиксируй его композиционную роль.

Пример:

**Primary scene object**
Должен занимать приблизительно одинаковую степень визуального внимания на всех viewport.

**Secondary object**
Не должен неожиданно становиться крупнее primary object после смены breakpoint.

**Background scenery**
Не должна превращаться из фонового слоя в главный элемент только из-за изменения aspect ratio.

Проверяй не абсолютный размер в пикселях, а:

> относительную визуальную массу объекта внутри viewport.

Если объект занимает 20% внимания на Desktop и 50% на Mobile — это должно быть осознанным решением, а не побочным эффектом responsive layout.

---

# PRINCIPLE 4 — DEPTH

Страница должна восприниматься как пространство, а не как набор PNG-слоёв.

Для каждой сцены определить:

- foreground;
- middle ground;
- background;
- distance from viewer;
- overlap;
- atmospheric separation;
- motion relationship.

Используй глубину последовательно.

Не допускай ситуации, когда все объекты выглядят расположенными на одной визуальной плоскости.

---

# PRINCIPLE 5 — CONTINUOUS JOURNEY

Основной визуальный сценарий должен ощущаться как:

> путешествие через пространство / культуру / время.

Не как:

> фон → появился объект → исчез → появился следующий объект.

Каждая следующая сцена должна визуально вытекать из предыдущей.

Проверь переходы:

Scene A → Scene B  
Scene B → Scene C  
Scene C → Scene D

Для каждого перехода определить:

- что остаётся визуальной опорой;
- куда движется взгляд;
- что появляется раньше;
- что исчезает позже;
- как сохраняется ощущение пространства.

Избегай полного композиционного reset между сценами.

---

# PRINCIPLE 6 — HERO CONSISTENCY

Hero должен иметь одну смысловую модель.

Не допускай, чтобы:

Desktop:
hero = massive centered typography

Tablet:
hero = small side typography

Mobile:
hero = massive typography again

если это не имеет явного композиционного основания.

Определи единый характер hero.

Например:

- cinematic central statement;
- editorial left-aligned statement;
- immersive layered hero.

После выбора сохраняй его характер на всех viewport.

Размер может меняться.

Композиционная роль — нет.

---

# PRINCIPLE 7 — SCENE LABEL SYSTEM

Создай единую систему подписей.

Зафиксируй:

- typography;
- font size rules;
- visual weight;
- padding;
- border/radius;
- background treatment;
- distance from target object;
- alignment;
- anchoring logic.

Каждая подпись должна выглядеть привязанной к конкретной сцене.

Запрещено размещать label просто там, где осталось свободное место.

Для каждой подписи должен быть понятен ответ:

> Почему она находится именно здесь?

Если такого ответа нет — позиция неудачна.

---

# PRINCIPLE 8 — MOUNTAIN / BACKGROUND CONTROL

Фоновые ландшафты должны сохранять свою функцию.

Проверь mountain panorama отдельно.

На каждом viewport определить:

- высоту горизонта;
- долю viewport;
- depth;
- crop;
- opacity/contrast;
- relationship with foreground.

Не позволяй landscape элементу случайно становиться доминирующим в portrait.

Если на Mobile он занимает больше места, это должно усиливать композицию, а не изменять её смысл.

---

# PRINCIPLE 9 — FINAL SCENE

Финальная сцена должна восприниматься как визуальный climax.

Она не должна становиться визуально слабее предыдущих сцен.

Проверь:

- luminance;
- contrast;
- focal point;
- readability;
- CTA hierarchy;
- separation text/background.

Исправь чрезмерное затемнение.

CTA должен быть очевидно интерактивным и иметь достаточный визуальный приоритет.

Заголовок должен считываться мгновенно.

Не превращай финал в светлую сцену только ради контраста.

Сохрани атмосферу, но создай контролируемую световую иерархию.

---

# PRINCIPLE 10 — TABLET QUALITY GATE

Проведи отдельный Tablet Review.

Tablet нельзя считать пройденным автоматически после Desktop и Mobile.

Проверить:

- landscape;
- portrait;
- 768 px;
- ~820 px;
- ~1024 px;
- промежуточные значения.

Для каждого состояния задай вопрос:

> Выглядит ли это как композиция, которую дизайнер специально создал для этого viewport?

Если ответ:

> «Похоже на промежуточный breakpoint»

— результат не принят.

---

# VISUAL HIERARCHY TEST

Для каждого viewport проведи 5-second test.

После пяти секунд просмотра должно быть понятно:

1. Что является главным элементом?
2. Что является вторым по значимости?
3. Куда должен двигаться взгляд дальше?
4. Какой элемент интерактивный?
5. Где находится следующий этап истории?

Если порядок неоднозначен — исправить композицию.

---

# SILHOUETTE TEST

Временно игнорируй текстуру, фотографии и декоративные детали.

Оцени страницу как набор крупных масс.

Проверь:

- balance;
- negative space;
- dominant shapes;
- density;
- rhythm;
- focal points.

Если композиция работает только благодаря красивым изображениям, а без них разваливается — структура недостаточно сильная.

---

# GRAYSCALE TEST

Оцени композицию без цвета.

Проверить:

- hierarchy;
- luminance;
- readability;
- separation;
- CTA;
- hero;
- scene labels.

Если важные элементы теряются без цвета — усилить hierarchy.

---

# SCROLL RHYTHM

Просмотри страницу как непрерывную scroll-композицию.

Оцени:

- начало;
- acceleration;
- pauses;
- reveal;
- transition;
- climax;
- ending.

Избегай равномерного:

scene → scene → scene → scene.

Создай ритм.

Некоторые моменты могут быть:

- плотными;
- спокойными;
- быстрыми;
- широкими;
- интимными.

Но эти изменения должны быть контролируемыми.

---

# CROSS-VIEWPORT COMPARISON

После отдельной проверки каждого viewport расположи рядом:

- Desktop;
- Tablet Portrait;
- Tablet Landscape;
- Mobile.

Сравни:

## Hero
Одинакова ли роль?

## Objects
Сохраняется ли относительная иерархия?

## Horizon
Сохраняется ли пространственная модель?

## Labels
Работает ли одна система?

## CTA
Сохраняется ли hierarchy?

## Story
Рассказывают ли все версии одну историю?

Любое существенное расхождение должно иметь объяснимую причину.

# VISUAL DEFECT PRIORITY

Исправляй проблемы в следующем порядке.

## P0 — Art Direction

- разные композиционные языки;
- неправильная hierarchy;
- разрушенная spatial model.

## P1 — Scene Composition

- масштаб;
- depth;
- framing;
- horizon;
- relative object sizes.

## P2 — Responsive Composition

- Tablet;
- Mobile;
- intermediate viewport.

## P3 — Typography / Labels / CTA

- positioning;
- scale;
- readability;
- hierarchy.

## P4 — Motion / Transitions

- continuity;
- timing;
- visual journey.

## P5 — Decorative Polish

- shadows;
- subtle gradients;
- micro-spacing;
- tiny offsets;
- fine animation polish.

Не начинай P5, пока P0–P3 не решены.

---

# WHAT 9/10 MEANS

Visual Quality 9/10 допускается только если:

- одна арт-дирекция сохраняется на всех viewport;
- Desktop, Tablet и Mobile выглядят намеренно спроектированными;
- нет заметных breakpoint-компромиссов;
- hierarchy понятна;
- композиция стабильна;
- относительный масштаб объектов контролируется;
- сцены имеют глубину;
- переходы ощущаются частью одного путешествия;
- labels имеют системное поведение;
- CTA визуально очевиден;
- финальная сцена имеет сильный climax;
- нет значимых визуальных дефектов;
- остаются только несущественные polish-улучшения.

---

# WHAT 10/10 MEANS

Не используй 10/10 как синоним «багов нет».

10/10 означает:

- композиция не просто корректна, а сильна;
- responsive-адаптации кажутся авторскими, а не вынужденными;
- визуальная история считывается без объяснений;
- каждый крупный объект находится именно там, где должен;
- нет очевидного решения, изменение которого существенно улучшило бы результат;
- motion, typography, imagery и composition работают как одна система.

10/10 должно быть редкой оценкой.

---

# REMEDIATION OUTPUT

После анализа не ограничивайся замечаниями.

Сформируй конкретный план исправлений.

Для каждого дефекта:

### Issue

Что визуально неправильно.

### Root visual cause

Не техническая причина в коде, а композиционная причина.

Пример:

не «left: 30px неправильный»,

а:

«Tablet layout потерял центральную композиционную ось и поэтому hero воспринимается случайно смещённым».

### Target state

Как должен выглядеть исправленный результат.

### Cross-viewport rule

Как решение должно вести себя на Desktop / Tablet / Mobile.

### Priority

P0 / P1 / P2 / P3 / P4 / P5.

# FINAL VISUAL GATE

Считай визуальную работу завершённой только если:

**Desktop ≥ 9/10**  
**Tablet ≥ 9/10**  
**Mobile ≥ 9/10**  
**Cross-platform consistency ≥ 9/10**  
**Overall Visual Quality ≥ 9/10**

При этом запрещено повышать оценку только потому, что дефекты технически исправлены.

Оценка должна отражать качество конечной композиции.

Главный финальный вопрос:

> Если убрать информацию о breakpoint и показать Desktop, Tablet и Mobile рядом профессиональному арт-директору, будет ли очевидно, что это три адаптации одного сильного, намеренно спроектированного визуального произведения?

Если нет — визуальная работа ещё не закончена.
